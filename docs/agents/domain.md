# Domain docs

This repository uses a single-context layout:

- `GLOSSARY.md` at the repository root defines domain terms.
- `docs/adr/` contains architecture decision records.

Before exploring the codebase, read the glossary and ADRs relevant
to the task.

If these documents are absent, proceed silently. The domain-modeling
skill creates them when terms or decisions are resolved.

Use glossary terms consistently in issues, code, tests, and proposals.
Flag missing concepts for domain modeling when they reveal a real gap.

If a proposal contradicts an ADR, name that ADR and explain why the
decision should be reconsidered.
